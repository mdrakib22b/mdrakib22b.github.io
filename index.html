    What building them taught me
    
      
    Each of these came from something breaking.
    
      
    
        
    Wait for an event. Don't poll.
    The packet printer runs only when mail arrives. Between emails nothing is running at all. A scheduled task checking the inbox every few minutes would have run all day for something that happens a few times.
    
        
    Check the parse before building on it
    The first dashboard read the wrong column and hid four real follow-ups. I only caught it because the list looked too short. Now every parser gets checked against the source file before anything is built on top of it.
    
        
    Anything from an email is untrusted
    A folder link in an email body is only opened if it sits under a known root and names the job in the subject. The handler behind a clickable link assumes hostile input and never runs a file.
    
        
    Publish a clean copy, never a branch
    Work code goes public as a new repository with fresh history, renamed terms and generated data. A spreadsheet is a zip file, so the scan for leftovers goes inside the binaries too.
    
        
    Time the old way first
    Most of my before numbers are estimates. They make the case for the work, so next time I'll measure the manual process before I replace it.
